**Actual execution path and model contracts.** [verified: static_code, with indicated CPU checks]

QF queue launchers invoke `queue_cli` workers; `queue_worker.py:13–29` claims queue jobs and invokes their stored command. `qf_runner.py:34–48` loads the queue row, rejects unsupported protocol/features, resolves `matched_temporal_v1.yaml`, calls `load_data`, and dispatches a shared fit or S shard. Stage-2 launchers invoke `discrimination_cli`; `discrimination_runner.py:18–62,114–127` resolves model overrides/selected configs, trains, selects checkpoints, and writes predictions. These launchers were inspected, not launched.

`qf_training.load_data` (`:84–85`) discovers sorted CSV stems and calls `cli.parallel.bake_tensors` (`:78–129`). It does not load a persistent tensor cache. `data/preprocess.convert_and_detect_files` (`:30–56`) is the separate workbook-to-CSV conversion: first worksheet via pandas, only when the destination CSV does not already exist. There is no source checksum/freshness check. The QF launcher therefore uses existing CSVs directly, not proof of a fresh workbook conversion. No converter or baking job was executed in this audit.

`LOBDataset._get_common_dates` (`data/dataset.py:51–56`) intersects all selected assets' dates. `bake_tensors` groups per asset-day, left-joins the fixed grid, forward-fills within that day, then zero-fills (`:84–99`). It transforms all days in memory before splitting, but the own-asset transformation has no fitted population statistics. QF splitting uses complete days and `int(n*.7)`, `int(n*.8)` (`qf_training.py:40–41`). Training shuffles days; history within each day is causal. Stage-2 factor scaling is fitted only on the first 70% of days (`discrimination_factors.py:33–45`).

All principal QF models use 13 no-investor features, d_model 128, two causal temporal Transformer layers, eight heads, feed-forward width 512, post-norm layers, learned 38-position embeddings, and dropout 0.1 unless overridden. The history for origin t is the same day's sequence from 09:00 through t. Time attention includes its diagonal. There is no cross-day memory. The main feature transforms are fixed log midprice, two log level-1 relative prices, and ten log1p depth quantities (`data/transforms.py:14–36`). No per-asset fitted standardizer, corporate-action adjustment, or general price clipping is present. `nan_to_num` handles nonfinite transformed values (`cli/parallel.py:123–125`), which is a code modification of values and not provider provenance.
